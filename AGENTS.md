# AGENTS.md

diskmap: Windows disk-usage treemap. Rust workspace, Tauri 2 desktop app, plain HTML/CSS/ES-module front end.

## Layout

- `crates/core`: tree, squarified layout, filter grammar (`src/filter`), tags, file classes, snapshot and timeline formats, diff, retention, report, schedule task XML. No I/O.
- `crates/scan`: walk backend (`walk.rs`), MFT backend (`mft.rs`, `mft/record.rs`), watcher (`watch.rs`), live updater (`live.rs`), volume info.
- `crates/bench`: `diskmap-bench` CLI (`scan`, `compare`, `watch`). Development tool only: excluded from `default-members`, so plain `cargo build` skips it; build it with `-p diskmap-bench` when needed; never ship it in release archives.
- `crates/desktop`: the app (binary `diskmap`). Backend in `src/` (`commands.rs` Tauri commands, `session.rs`, `state.rs`, `paint.rs`, `config.rs`, `watch.rs`, `timeline.rs` timeline store and reports, `headless.rs` `--snapshot` runs, `scheduler.rs` Task Scheduler, `toast.rs`, `update.rs` updater, `snapstore.rs` snapshot store, `compare.rs` compare mode; full list in `docs/architecture.md`, Desktop modules). Front end in `ui/` (`index.html`, `style.css`, `js/*.js`, no build step). `build.rs` lists the commands; a new command goes in `build.rs`, `main.rs`, `ui/js/api.js` and `capabilities/main.json` (`allow-<name>`), with its generated `permissions/autogenerated/<name>.toml` committed. Updates: `src/update.rs`, `ui/js/update.js`. Winget templates: `winget/manifests/`. `windows/hooks.nsh`: NSIS installer hooks.
- `assets/icon/`: icon source and renders; `crates/desktop/icons/` holds copies.
- `tools/shots/`: window capture scripts. `docs/`: architecture, scanning, filters, branching, distribution (installer, updater keys, winget).
- `.local/` holds local working files (e.g. `.local/space_sniffer/`, a third-party reference app). Do not read `space_sniffer`, edit it or commit anything in `.local/`.

## Build, test, lint

```powershell
cargo build --release -p diskmap
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Installer (NSIS, needs the Tauri CLI: `cargo install tauri-cli --version "^2" --locked`):

```powershell
cd crates\desktop
cargo tauri build --bundles nsis   # target\release\bundle\nsis\Diskmap_<version>_x64-setup.exe
```

If `target\release\diskmap.exe` is locked by a running app, add `--target-dir target\tauri` to cargo commands.

## Rules

- Branches follow `docs/branching.md`: work from `develop`, `main` holds releases only.
- Never commit `.local/`, `target/` or `diskmap.toml`.
- Never kill `diskmap.exe` or any process you did not start.
- Do not commit or push unless asked.

## Code style

- English only. Small functions.
- Short doc comments on public items only. No long explanatory comments.
- Keep `unsafe` blocks small, each with a `// SAFETY:` line.
- No new dependencies without a reason.
- Front end: plain ES modules, no build step, no Node, no npm.

## UI rules

- Terse, tool-like interface in the spirit of VS Code, GitHub and Obsidian.
- Labels of one or two words. No sentences in the UI.
- Icon buttons with tooltips.
- Themes are data (`ui/js/themes.js`, `ui/js/scheme.js`, `style.css` variables).
- The map keeps its own look: rounded tiles, gaps, grey folders, accent-coloured files. Do not copy SpaceSniffer's colours or frames.
- Map behaviour follows SpaceSniffer: click digs in place, double click zooms, Back and Forward step over zooms only.

## Visual verification

Look at screenshots before saying UI work is done.

1. Build, then start the exe with test switches (a config copy avoids touching `diskmap.toml`: set `DISKMAP_CONFIG`):
   `diskmap.exe <path> [switches]`
2. Find the window: `powershell -File tools\shots\list.ps1 -ProcId <pid>`.
3. Resize and capture only that window: `powershell -File tools\shots\win.ps1 -Handle <hwnd> -Width 1600 -Height 1000 -Shot out.png`. The script can also post `-Action click|double|right|move|key` to the window.
4. Read the PNG. Stop the process you started when done.

Test switches (`crates/desktop/src/args.rs`), applied after the scan of the last tab ends unless noted:

- `<path>`: open a tab scanning that folder; repeat for more tabs.
- `--tabs "a;b;"`: tabs separated by `;`; an empty entry is a start tab (the dashboard; `--tabs ";"` opens one). Seed its history with a few `--snapshot <root>` runs first.
- `--select <rel>`: select the node at a path below the scan root.
- `--zoom <rel>`: zoom to the node at that path.
- `--hover <rel>`: hover the node.
- `--tooltip <rel>`: hover the node and show its tooltip.
- `--detail <n>`: set the detail level.
- `--side`: show the side panel.
- `--compare <latest|path>`: compare against a snapshot of the root; `latest` is the newest one not saved by this scan.
- `--settings <section>`: open Settings at startup (Appearance, Map, Scan, Schedule, Snapshots, Classes, Keys, About); applied at startup.
- `--theme <name>`: theme for this run; applied at startup.
- `--scale <percent>`: UI scale for this run; applied at startup.
- `--log`: show the Output panel; applied at startup.
- `--colour <accent|class|age>`: file tile colours for this run; applied at startup.

Headless switches: `--snapshot <root>` (repeatable) runs without a window before Tauri starts. It scans each root with the
configured backend, writes a timeline point, applies retention, appends a line to `reports.jsonl`, shows a toast and exits
with 0, or 1 when a root failed. `--quiet` drops console output, `--no-toast` the toast. The scheduled task runs
`diskmap.exe --snapshot <root>... --quiet` (see `docs/snapshots.md`). Try it with a config copy and a small folder:
`diskmap.exe --snapshot C:\Temp --no-toast`.

`DISKMAP_CONFIG` sets the config file path. Without it, an exe outside the folder the installer recorded (`HKCU\Software\diskmap\InstallDir`), such as a dev build, is portable and uses `diskmap.toml` and `data\` next to itself (see `docs/architecture.md`, Storage paths). `DISKMAP_PERF` names a file that gets one layout timing line per layout.

## MFT and elevation

The MFT backend needs administrator rights, so tests and runs from a normal terminal only cover the walk backend and the pure record parsing tests. Without elevation these cannot be checked:

- An MFT scan of a real volume and the Elevate relaunch.
- Walk against MFT differences.

From an administrator terminal:

```powershell
cargo test --workspace
cargo test -p diskmap-scan -- --ignored   # matches_walk_on_real_volume
cargo build --release -p diskmap-bench
target\release\diskmap-bench.exe compare C:\
target\release\diskmap-bench.exe scan C:\ --backend mft
```

See `docs/scanning.md`.
